# Plan — v2.0 Beta documentation rebuild & release

**Date:** 2026-08-20
**Planned with:** Opus · **Execute with:** Sonnet
**Wave gate:** Beta exit (`docs/v2_platform/documentation_rebuild.md`, steps 1–6 + 8; step 7 is GA-only)

---

## 1. Intended outcome

1. `v2.0-beta` published as a **GitHub pre-release** with English release notes
   (highlights, what changed, features by epic, breaking changes, known limitations).
2. The repository reads as **English-only** to an OSS visitor: no user-facing pt-BR
   Markdown remains.
3. v1-era documentation is **relocated** to `docs/archive/v1/`, not deleted, with every
   inbound link repaired.
4. Entry-point docs (`README.md`, `DESCRIPTION.md`, `CHANGELOG.md`, `docs/roadmap.md`,
   `docs/feature_matrix.md`) describe the **Beta** platform, not the Alpha wave.

## 2. Hard constraints

- **Markdown only.** No `.py` / `.ts` / `.tsx` / `.yaml` / `Makefile` edits.
  `git diff --name-only main` must match `\.md$` (plus the plan file itself).
- **No test runs, no `make check`.** Nothing this plan touches can change behavior.
- **Docstring pass is a no-op.** A comment/docstring scan over all 724 tracked source
  files found **zero** Portuguese. Do not re-run it and do not edit source comments.

### Pinned file — do not move

`docs/agents/agent-coder-v1-baseline.md` is asserted to exist at that exact path by
`backend/tests/unit/agents/test_agent_coder_plugin.py:41`. **Leave it in place.**
(The `docs/implementation/agent_spec.md` references in
`backend/tests/unit/repository/test_*.py` are synthetic `tmp_path` fixtures and are
*not* affected by moving the real file.)

## Phase 1 — Translation (`story/beta-docs-s1-translate`)

### 1a. Build the glossary first (blocking, single agent)

Parallel translation without a shared glossary produces drifting terminology in a
*canonical* document. Before any chunk is translated, produce
`scratchpad/glossary.md` mapping every recurring domain term, e.g.:

```
Fluxo → Flow            Motor de Fluxos → Flow Engine
Habilidade → Skill      Plano de Execução → Execution Plan
Roteamento → Routing    Ponto de Extensão → Extension Point
Seleção → Selection     Núcleo Pequeno → Small Core
Aprovação → Approval    Estado Durável → Durable State
```

Seed it from terms already used in English elsewhere in the repo (`docs/flows/spec.md`,
`docs/plugins/manifest.md`, `docs/agents/runtime.md`, `progress.md`) so the translated
reference doc agrees with the docs that survive to GA. **Do not invent new terminology.**

### 1b. Chunk, translate in parallel, reassemble

Do **not** have multiple agents edit the same file — split it instead:

1. Split `docs/architecture/v2_platform_reference.md` at `^## ` boundaries into
   ~450-line chunk files in the scratchpad (~18 chunks). Record the chunk order.
2. Dispatch one subagent per chunk, in parallel. Each agent receives: its chunk file,
   `glossary.md`, and these rules:
   - Translate prose, headings, table cells, list items, admonitions.
   - **Never** translate: fenced code blocks, inline code, YAML/JSON keys and values,
     file paths, identifiers, env-var names, `E<n>-S<m>` labels, ADR/RFC ids, URLs.
   - Preserve heading levels, anchors, numbering, table structure, and line intent —
     the file is cross-referenced by section number (`§18.9`) from `progress.md` and
     from 16 code/config sites.
   - Return the translated chunk only, no commentary.
3. Reassemble in recorded order into the original path. Confirm the `^## ` heading count
   is still **55** and section numbering `1..24` is intact.

### 1c. §21 Appendices — align, don't re-translate

§21 (line ~6817) embeds pt-BR copies of the ADR / RFC / DoR / DoD / story templates that
already exist **in English** under `docs/v2_platform/templates/`. Match the existing
English wording verbatim rather than producing a second, divergent translation.

## Phase 4 — Release

### 4a. Notes

Draft `scratchpad/RELEASE_NOTES_v2.0-beta.md` (scratchpad — the notes live in the GitHub
release, not the repo):

- **Highlights** — small core + typed extension points; real governed task execution;
  isolated-by-default sandbox; Control Center UI; global `autodev` install.
- **What changed since v1** — architecture inversion, pipeline → plugin/agent/flow model.
- **Features by epic** — E3–E18, E32–E35, each one line, sourced from `CHANGELOG.md`.
- **Breaking changes** — carry forward the E11-S4 production-compatibility note
  (fail-closed backups, rejected default PostgreSQL/MinIO credentials).
- **Known limitations** — the three open Beta gate criteria, verbatim and unhedged:
  retrieval p95 benchmark unrun; no numeric streaming-latency assertion; backup/restore
  RPO/RTO never exercised in staging. Plus the two `[~]` partials (no composed
  end-to-end rehearsal beyond `beta_acceptance_flow.md`; WCAG is component-level only).
- **Upgrade / install**, **What's next (GA / E13)**.

### 4b. Merge, then tag

```bash
# epic → main via PR (never merge an epic directly)
gh pr create --base main --head epic/beta-exit-documentation-rebuild \
  --title "docs: v2.0 Beta documentation rebuild" --body-file <summary>

git switch main && git pull
gh release create v2.0-beta --prerelease \
  --title "AutoDev Architect v2.0 Beta" \
  --notes-file /path/to/scratchpad/RELEASE_NOTES_v2.0-beta.md
```

Then delete merged story + epic branches locally and remotely.
